# Mission control: operating and qualifying a shift

Open **Shift control → Needs attention**, choose a finding, then read its reported cause, impact, evidence age and next investigation. For an owner question, expand **Decision readiness** before leaving the console. A recorded question can be real even when its permitted responses, revision, current budget and effect receipt are unknown.

## Local setup

For a fixture tour, run `python3 -m http.server 8765 --bind 127.0.0.1 --directory apps/rizzstack-hive` and open `http://127.0.0.1:8765/?demo=dense`. For a real observation, use [the Orbit host integration](HIVE_INTEGRATION.md). The reviewed host and content-addressed pane must match. Use the existing publisher, with `--id rizzstack-hive --version 1.0.0 --title 'The Hive'`, in a private runtime. Use Orbit’s normal disabled-first registration. Grant **Share read-only overview with this Hive pane** in the trusted host.

1. **Follow one attempt.** Choose an attempt, **Open Rails timeline**, then **Inspect history**. When the initial read establishes a valid cursor, Signal watch can report the selected stream. A subsequent invalidation triggers an authoritative reread subject to the overview’s 30-second floor. The selected history can change first. Only a newer accepted snapshot can change the in-flight count. On loss or reset the UI reports the gap or reconnect; an event notification alone establishes no worker or verifier outcome.
2. **Read companion evidence.** Optionally configure `ORBIT_HIVE_REPORT_DIR` on a private local Orbit instance. It names **one explicitly enrolled publication directory**, not a queue store. On supported Linux systems the path and ancestors must meet the descriptor reader’s ownership, mode and mount checks (`server/hive-reports.mjs`); use a service-owned 0700 directory and atomic 0600 files. Do not use a shared scratch directory. After the overview connects, click **Share enrolled evidence with this pane**. Open **Workbench → Queue** or **Release desk**. Stopping evidence sharing discards the granted document. All reports are opt-in, separately dated, and absent until published. No background publisher is installed.
3. **Publish a single coordinator subject.** Use [BundleBees #93](https://github.com/mojomast/bundlebees/pull/93)’s `python3 -m bundlebees_plugin.hive_docket --help` and [producer guide](https://github.com/mojomast/bundlebees/blob/a9e8b16/docs/hive-docket.md). The selected feature/job, native queue, scheduler, signed lease and verifier evidence yield `queue.json`. This is a **file coverage** observation of one selected head. Three files covered is not three acceptance criteria passed. The existing disconnected demonstration remains labeled separately. Pinned test input and digest instructions: [host journey](HIVE_MISSION_QA.md).
4. **Publish current GitHub observations.** `python3 scripts/hive_release_read.py --staging-dir /absolute/private/publication-dir --include-hive` captures the four enrolled components and their named PRs into `release.json`. Re-run it to refresh. Check runs are bound to a SHA; they are not a configured required-check or cross-stack verdict. The historical Rails qualification remains below the separately dated report.
5. **Publish names for a new project.** Follow [public alias enrollment](HIVE_PUBLIC_LABELS.md). The producer binds separately authored public aliases to a reviewed snapshot. The host forwards only titles for matching, visible, fresh job/feature records. Job prompts and private owner questions are not a label source.
