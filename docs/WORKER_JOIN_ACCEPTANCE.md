# Worker join: offline kit, enrolled transport and verification

## Stage an OCI kit

`python3 scripts/worker-join/stage-oci.py --layout /absolute/local/layout --stage-parent /absolute/private/kits --approved-image REGISTRY/REPOSITORY@sha256:DIGEST` stages one OCI image manifest, its config and its referenced compressed or plain layer blobs. Supply an independently approved full digest, not a tag or a hash copied from the input index. Use a trusted checkout and owner-controlled directories. The command does not fetch, unpack, load or start an image. Re-running on the staged kit verifies its bytes even without the source layout. It does not validate publisher signatures or scan image contents. Multi-platform index pins require selection and separate approval of a single platform manifest. No production image or approval was supplied here; the test image contains a single notice file.

## Enrolled OpenSSH

`scripts/worker-join-peer.mjs PRIVATE_RUNTIME PORT` exposes **only** the existing worker operations on a dedicated numeric loopback socket. Run only against an existing owner-initialized join registry. The ordinary inventory/owner port is never the forwarding destination. The peer rejects an owner operation even with a valid owner token. No listener is automatically started. On a separately owned SSH host, the operator must first enroll a dedicated client key and independently verify the exact server Ed25519 public key. Use an account restricted to public-key authentication, no agent/stream-local/remote forwarding, no tunnel, `MaxSessions 0` (no shell, command or subsystem), `AllowTcpForwarding local`, and `PermitOpen 127.0.0.1:PEER_PORT`. Restrict the enrolled key to that same destination. Do not widen the ordinary Orbit host-management key. Rotation and removal of this account/key are independent of application revocation.

The worker supplies a canonical absolute `enrollment.json` in a private `0700` directory, beside `peer.key`, both owner-owned `0600` regular files. JSON fields: `address` (one exact private IPv4 or `127.0.0.1`), `sshPort`, `user`, `hostKey` (`ssh-ed25519` and full base64 key, no comment), and `peerPort`. The owner supplies this file out of band; the invitation cannot alter it. `node scripts/worker-join/ssh-peer.mjs /absolute/private/enrollment.json < private-invitation.json` joins and reports one heartbeat. The exported `enrolledSshJoin` provides the same session methods for claim/status/report. Orbit's existing SSH config renderer, strict known_hosts verification and OpenSSH `-W` carry HTTP over direct-tcpip with no worker listener, proxy command or remote session. Test traffic stayed on loopback. The OpenSSH client passed against the installed Paramiko test server; this host's real sshd could not enter privilege separation (`setgroups` denied).

## Verify a synthetic BundleBees brief

`node scripts/worker-join-brief-rehearse.mjs /absolute/bundlebees APPROVED_FULL_COMMIT /absolute/gitleaks APPROVED_BINARY_SHA256` uses a fresh runtime and repository. Pass independent pins. The coordinator imports tracked BundleBees source from the named Git object; it hashes a private copy of the scanner before executing it. It uses `JsonQueue`, `QueueStore.claim`, and `leases.record_lease` to bind an eligible item to a base revision and one file. The worker reports one integer under an attempt-bound grant. It cannot submit a command, patch, file path, test, or acceptance decision. The coordinator transforms that integer into a change to `total.txt`. Its fixed data test runner reads two bounded files and never interprets source or spawns a command. This deliberately uses the verifier's TestRunner interface, not its general-purpose sandbox backend.

`verify_local.verify_and_commit` checks the signed lease, RED before the change, GREEN and suite after, and runs mandatory Gitleaks. `integrate_job.integrate` runs the combined suite and checks ancestry in the throwaway repository. Only an accepted wave and a final comparison against the **still-authorized** report can mark the Orbit attempt accepted. Revocation quarantines pending claims/reports. The fixture removes its private candidate Git objects and closes its listener. No repository in the workspace is committed to or pushed. This rehearsal is the private coordinator implementation for the finite `sum-v1` brief, not a general queue daemon.

## Tailcat preflight

`scripts/worker-join/tailcat-plan.mjs` checks an explicitly supplied local binary against an independently approved SHA-256 and the exact CLI contract documented in [upstream v0.7.0](https://github.com/tailscale/tailcat/blob/v0.7.0/README.md). No binary digest is supplied by Orbit. It returns argument arrays, never executes them. The plan uses `serve --key=new --allow=<client node key> <peer port>` (avoids silently reusing a saved default key) and `forward <tc-address> <port>:<port>` with its default loopback bind. PSK stays enabled. Only the dedicated worker peer may be named. The address is a secret and is excluded from the serialized plan. This does not validate native compatibility, enroll an identity, start a listener, or prove NAT traversal. The existing untested SSH `ProxyCommand tailcat connect` is not used. Upstream gives no API/CLI/wire stability guarantee; the original trust model was same-person endpoints. Public DERP is rate-limited; self-hosted DERP is an option. Tailcat is point-to-point, not a mesh or Headscale.
